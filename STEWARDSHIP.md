# Domain Governance Baseline stewardship

## Position

The Domain Governance Baseline is a small authored governance artefact by Bryan Chetcuti.

Its purpose is to help organisations determine whether the fundamentals of domain ownership, authority, renewal, DNS, email trust, dependencies, change control and incident readiness are understood and governed, then move unresolved work into existing organisational governance.

It is not a product, assessment platform, maturity model, certification scheme, assurance service or workflow system.

## Canonical baseline

Version 1.0 establishes the current ten questions as the canonical baseline.

The baseline should remain stable enough to cite and reuse. Stability does not mean immobility: explanation, examples, practical guidance, accessibility and supporting artefacts can improve as evidence from real use emerges.

### Versioning principle

- **v1.x** - clarification, correction or improvement that does not materially change the substance of the ten canonical questions.
- **v2.0** - considered only if a canonical question is added, removed or materially reframed.

Routine implementation changes do not require a substantive version change unless they alter the meaning or use of the artefact.

## Stewardship compass

Future changes should be driven by one or more of the following:

- evidence that wording is unclear in real governance use;
- a repeated implementation problem exposed by organisations using the baseline or guides;
- a material change in domain-layer governance practice that makes current guidance inaccurate or incomplete;
- accessibility or usability improvements that make the existing artefact easier to use;
- evidence from related work that strengthens explanation without changing the baseline into an observation or assessment product;
- citation or reuse needs that improve the artefact's stability and portability.

The default response to a new idea is not to add another feature, guide or assessment dimension. The first question is whether an existing part of the baseline or bounded practice guidance can be made clearer or more useful.

## Bounded practice guidance

The five-guide sequence remains intentionally complete and bounded:

1. establish a domain register;
2. control registrar and DNS authority;
3. govern email authority and public signals;
4. establish domain incident readiness;
5. run a recurring domain governance review.

A sixth guide is not part of the roadmap by default. Expansion requires a distinct, validated governance problem that cannot be addressed credibly within the existing baseline or guides.

## Relationship to related work

The Domain Governance Baseline remains standalone.

Related work such as the .au Domain Observatory (.auDO), ThreatScope Check and TrustSurface can inform, evidence or contextualise domain-governance questions, but none is a normative dependency of the baseline.

In particular:

- public observation can support evidence, but cannot answer internal governance questions;
- the baseline should not become an automated public-signal assessment;
- the baseline should not inherit scoring, maturity or conformance concepts from another framework;
- cross-links should remain explanatory rather than structural.

> Chetcuti, B. (2026). *Domain Governance Baseline* (Version 1.0). https://baseline.bryanchetcuti.com/

## Success signal

The primary measure of success is independent citation and practical use, not traffic, assessment completions, feature count or expansion of the site.

Useful signals include:

- citation in governance papers, presentations, articles or professional guidance;
- use in organisational review or assurance preparation;
- adaptation of the baseline or starter records with attribution;
- practitioner feedback that results in a clearer or more accurate v1.x revision.

A future dedicated domain should be reconsidered only when the current personal subdomain creates evidenced citation or adoption friction, not for presentation alone.
