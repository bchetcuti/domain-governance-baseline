# Security Policy

## Supported Versions

Domain Governance Baseline is a small, static public web instrument rather than a packaged software product with multiple maintained release branches.

| Surface | Supported |
| --- | --- |
| Current deployed site and default branch | Yes |
| Historical tags, releases and reference snapshots | Not separately maintained |

Security fixes may be applied to the current implementation without changing the substance or citation identity of a published reference edition.

## Reporting a Vulnerability

Please report suspected security vulnerabilities privately rather than opening a public GitHub issue.

Where available, use **GitHub's private vulnerability reporting** for this repository:

1. Open the repository's **Security** section.
2. Select **Report a vulnerability**.
3. Provide enough information to reproduce and assess the issue.

Useful reports include:

- a clear description of the vulnerability;
- the affected page, file or component;
- steps to reproduce the issue;
- the potential security impact;
- any suggested remediation, if known.

Please avoid including unnecessary personal information, credentials, secrets or sensitive organisational data in a report.

Reports will be reviewed and assessed based on their reproducibility and potential impact. Confirmed vulnerabilities will be addressed in the current implementation as appropriate.

## Scope

Examples of issues appropriate for security reporting include vulnerabilities affecting:

- the integrity or delivery of the public website;
- client-side JavaScript execution;
- third-party dependencies or externally loaded resources;
- unintended collection, transmission or exposure of user information;
- repository or deployment configuration where it affects users of the published site.

Questions about the governance model, canonical ten questions, practical guidance, wording, methodology or proposed enhancements are **not security vulnerabilities** and should use the repository's normal issue or contribution process.
